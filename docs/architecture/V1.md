# Stella Runtime V1 architecture

> Status: normative target architecture
> Requirement source: [`../requirements/V1.md`](../requirements/V1.md)

The concrete V1 record shapes and invariants are defined in
[`DATA-CONTRACTS.md`](DATA-CONTRACTS.md).

## 1. Ownership model

| Owner | Authoritative assets | Excluded assets |
| --- | --- | --- |
| Runtime repository | Generic source, contracts, CLI, Plugin Skill, adapters, synthetic fixtures, compatibility evidence, package and release automation | Private instance knowledge, identity, credentials, live state, real experience |
| Authority Repository | Private knowledge, identity, configuration, package pin, migration intent, private Instance Test Pack | Runtime source or copied public contracts |
| Git-external Runtime storage | Current State ledger/head, outbox, state views, cognitive overlay, rebuildable projections | Source code or durable knowledge authority |

Runtime is independently implementable and releasable. An Authority Repository is
one consumer, not a specification source. The only required cross-repository
operation is that a recovery orchestrator may invoke the public recovery
interface and transport its opaque immutable artifact.

## 2. Runtime pipeline

```text
Authority revision + Current State ledger
  -> validated immutable State View
  -> staged generation + registry + governing digest
  -> atomic generation activation
  -> before_prompt_build(run_id)
       -> bind generation, View, governing context
       -> one Router decision
       -> strict local validation
       -> explicit context packet
  -> OpenClaw Agent loop and native memory tools
  -> after_tool_call observations
  -> at most one before_agent_finalize remediation
  -> agent_end overlay commit and scratch cleanup
  -> explicit correction transaction
  -> outbox delivery to a distinct successor Run
```

## 3. Deep modules and external seams

The public interfaces are intentionally small. Host quirks, storage layout,
schema migration, retries, and validation remain inside their implementations.

| Module | Interface | Responsibility hidden behind the interface |
| --- | --- | --- |
| Authority | `parse`, `validate`, `resolveStableId` | Markdown/frontmatter parsing, reference validation, authority roles |
| Generation | `build`, `verify`, `activate` | staging, checksums, projection creation, atomic visibility |
| Router | `route` | host completion, timeout, JSON parsing, schema and registry validation |
| Run Scratch | `acquire`, `observe`, `claimRemediation`, `release` | run correlation, idempotency, TTL, lifecycle, capacity |
| State | `view`, `correct` | event ledger, head, immutable views, correction transaction |
| Reanswer | `claim`, `complete`, `release` | outbox CAS, attempts, successor binding, retry safety |
| Provenance | `record`, `query` | role-aware overlay minimization and native-audit linkage |
| Recovery | `backup`, `verify`, `restore` | consistent snapshots, compatibility, migration, rollback |

OpenClaw-specific details are isolated in exact-version adapters. Domain modules
do not expose hook payloads, Gateway commands, SQLite tables, database paths,
provider credentials, or session-store internals.

## 4. Run consistency model

`before_prompt_build` requires a non-empty `run_id`. `RunScratchMap` creates or
returns one immutable binding containing generation, authority revision, State
View, Router result, and observed stable references. A repeated prompt-build hook
for the same Run reuses this binding.

`after_tool_call` records a validated observation idempotently by `toolCallId`.
`before_agent_finalize` may claim one remediation revision if required retrieval
is absent. `agent_end` transactionally records the bounded overlay, completes or
releases any successor attempt, and clears scratch in `finally`.

Lifecycle reset, instance disable, restart, TTL expiry, and a hard capacity limit
provide secondary cleanup. Capacity exhaustion degrades new Runs; it never evicts
a live Run or falls back to session correlation.

## 5. Router and packet

The Router receives only bounded, already-resolved inputs. It returns a closed
JSON object containing routing status, ordinary framework selection, retrieval
plan, and reason codes. Runtime performs:

1. exact JSON parsing without fence stripping or substring guessing;
2. JSON Schema validation with no additional properties;
3. semantic validation of IDs, roles, generation, versions, and checksums;
4. governing-binding immutability checks;
5. deterministic degraded output on any failure.

The packet is assembled by code, not by the Router. It preserves authority roles,
contains stable references rather than copied private documents where possible,
and remains within configured size limits.

## 6. State, correction, and successor delivery

State storage is append-only. A correction transaction atomically:

1. appends a correction event;
2. advances `state_head`;
3. creates one pending `ReanswerOutbox` record.

Each session has at most one non-terminal outbox entry. A command continuation or
explicit UI normal RPC creates a host-owned Agent Run. Its prompt hook claims the
pending entry with CAS, binds the new `run_id` and new View, and injects a bounded
receipt. Success completes the entry; failure or abort returns it to pending.

Runtime does not directly start an unadmitted persisted-session embedded run,
write the host session store, or treat a UI `continueAgent` response as proof that
the server created a Run.

## 7. Generation and authority projections

Builder reads one authority revision and produces a staged manifest, normalized
records, Registry, governing digest, memory projection, and index metadata. Every
artifact carries `sync_generation`, source revision, contract version, and
checksum. Activation verifies the complete set and atomically switches one active
pointer for new Runs.

Derived content never writes back as authority. A failed activation leaves the
old generation active. Recovery and rebuild converge on the same target state;
they do not maintain old and new architectures in parallel.

## 8. Recovery architecture

`backup` establishes a consistent state boundary and writes a new immutable
snapshot plus manifest. `verify` is read-only. `restore` requires a target that
has not served a new Run, creates a rollback artifact, validates compatibility,
performs internal storage migration, verifies restored invariants, and either
commits or restores the target's prior state.

The manifest reports snapshot, storage, package, and contract versions; instance
ID; authority revision; active head and boundary; file checksums; pending outbox;
creation time; and projections requiring rebuild. Callers never learn table names
or file-copy ordering.

## 9. Exact OpenClaw adapter

The first adapter targets extended-stable `2026.6.34`. It uses typed hooks,
host-owned `llm.complete`, native memory results, command continuation, and UI
normal RPC. It does not use `api.runContext.*`, native structured output,
unadmitted `runEmbeddedAgent`, bundled-only scheduling, or unverified host
next-turn injection.

See [`../evidence/openclaw-2026.6.34.md`](../evidence/openclaw-2026.6.34.md).

## 10. Public/private verification split

Public tests own protocol, module, adapter, recovery, package, and synthetic
Golden coverage. A consumer may invoke the same public Runner with an external
Instance Test Pack. The Runner does not upload, copy, snapshot, or require that
pack for Runtime CI and release.
