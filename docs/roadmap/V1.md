# Stella Runtime V1 implementation roadmap

> Status: normative implementation sequence
> Requirements: [`../requirements/V1.md`](../requirements/V1.md)
> Architecture: [`../architecture/V1.md`](../architecture/V1.md)

The Runtime repository owns every generic deliverable below. Consumer-specific
knowledge migration, deployment configuration, private Golden tests, and product
acceptance are not Runtime blockers. Recovery is the one deliberate integration
seam: an external orchestrator may consume a released Recovery Snapshot contract.

## IMPL-01 — Repository, contracts, host seam, and test foundation

### Deliverables

- buildable single package and directory layout;
- public identity, manifest, strict config schema, compatibility manifest;
- versioned contracts, generated TypeScript types, runtime validation;
- Authority parser, stable ID resolver, Markdown section validator;
- empty or contract-first Router, RunScratch, MemoryObservation, Remediation,
  Reanswer, and RuntimeRecovery interfaces;
- synthetic unit, contract, integration, Golden, and pack-install test layers;
- optional external Instance Test Pack seam;
- exact `2026.6.34` package-install and capability smoke.

### Gate

Build, typecheck, tests, schema negatives, tarball allowlist, sensitive scan,
package install, Plugin inspect, CLI/Skill discovery, hooks, memory refs, scratch
cleanup, Router rejection, and successor adapter smoke pass with synthetic data.

### Issues

- [#1](https://github.com/tower1229/Stella-Runtime/issues/1): repository and package scaffold;
- [#2](https://github.com/tower1229/Stella-Runtime/issues/2): contracts and interfaces;
- [#3](https://github.com/tower1229/Stella-Runtime/issues/3): test Runner;
- [#4](https://github.com/tower1229/Stella-Runtime/issues/4): pack-install and host smoke.

## IMPL-02 — Current State, provenance, and recovery

### Deliverables

- SQLite migrations and append-only State Event Ledger;
- immutable State View derivation and active head;
- idempotent correction transaction and ReanswerOutbox;
- CAS claim, failure release, retry, and single-success completion;
- Cognitive Provenance Overlay storage and query CLI;
- distinct successor Run bound to the new View;
- Runtime Recovery Snapshot `backup`, read-only `verify`, rollback-safe `restore`.

### Gate

Concurrent idempotency, transaction rollback, old-Run View pinning, successor new
View, outbox interruption/retry, trace minimization, and all recovery corruption,
compatibility, interruption, and repeated-restore cases pass.

### Issues

- [#5](https://github.com/tower1229/Stella-Runtime/issues/5): authoritative state recovery;
- [#6](https://github.com/tower1229/Stella-Runtime/issues/6): Current State,
  provenance, correction, and safe re-answer.

## IMPL-03 — Plugin Runtime and first beta

Issue: [#7](https://github.com/tower1229/Stella-Runtime/issues/7).

### Deliverables

- one validated Router completion;
- Explicit Context Packet builder;
- four typed hooks and bounded RunScratch lifecycle;
- memory reference observation and at most one remediation;
- explicit degraded results and reason codes;
- Runtime CLI, self-check, bounded metrics, and minimized logs;
- pack-install verified `0.1.0-beta.x` release.

### Gate

Router cannot mutate governing binding; `none` cannot disable configured Kernel;
required retrieval remediates at most once; Plugin failure does not take over the
Agent loop; performance and privacy budgets pass; beta tarball contains only
allowlisted public assets.

## IMPL-04 — Generation and framework admission

Issue: [#8](https://github.com/tower1229/Stella-Runtime/issues/8).

### Deliverables

- generic Authority-to-Generation Builder;
- manifest, checksums, staging, verification, and atomic activation;
- Registry, governing digest, and memory/index projection metadata;
- packaged and discoverable `framework-admission` Skill;
- admission workflow that separates source author, model synthesis, and explicit
  user confirmation;
- projection rebuild and mixed-generation rejection.

### Gate

Only confirmed Cognitive content activates. Raw Evidence promotion, inferred
labels, broken refs, missing boundaries, mixed generations, and checksum drift
block activation. Failed activation leaves the prior generation serving.

## IMPL-05 — Release candidate and consumer conformance

Issue: [#9](https://github.com/tower1229/Stella-Runtime/issues/9).

### Deliverables

- explicit exact-version install and upgrade workflow;
- machine-readable package/version/contract/capability pin schema;
- `off -> observe -> enforce -> rollback` synthetic rehearsal;
- public consumer conformance Runner and recovery-orchestrator contract tests;
- restart continuity, upgrade compatibility, and previous-version rollback;
- release-candidate package and reproducible provenance evidence.

### Gate

Runtime conformance passes without any private repository. Optional external
Instance Test Packs can run locally without entering public logs or artifacts.
Recovery consumers use only the public interface and opaque snapshot.

## IMPL-06 — V1 stable release

Issue: [#10](https://github.com/tower1229/Stella-Runtime/issues/10).

### Deliverables

- public README, configuration reference, data-boundary guide, operations,
  upgrade, rollback, recovery, compatibility, and known-limitations documentation;
- npm trusted publishing/provenance, dependency review, release attestations, and
  tarball content audit;
- exact-host pack-install and compatibility evidence for `0.1.0`;
- stable release, changelog, support matrix, and rollback version record.

### Gate

All Runtime technical gates pass before publishing `0.1.0`. A consumer's product
usefulness judgment is valuable downstream evidence but is not required to
understand, build, test, or release the generic Runtime.
