# Telegram is the first confirmed approval channel

The first OpenClaw Confirmation Gateway supports Telegram presentation callbacks
only after exact 2026.6.34 smoke proves authenticated sender/account/chat/message
context, opaque routing, and Receipt issuance without LLM execution. Channels
without an equivalent Confirmed Channel cannot approve Authority Candidates and
must direct the user to Telegram; natural-language approval, ordinary text
commands, and OpenClaw's short-lived built-in Plugin Approval cannot weaken this
boundary. Review actions are `接受此版本`, `拒绝此版本`, and `请求改写`.
The last action is feedback rather than a final Receipt; acceptance of the newly
rendered Candidate records the final rewritten lineage. A high-entropy
Confirmation Routing Token is bounded by the same Discovery Authorization as
its Request and becomes unusable when that authorization ends or on decision,
withdrawal, invalidation, or successful publication.
